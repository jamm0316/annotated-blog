# evan.log 도메인 spec 과 @MX 주석

코드를 다시 읽지 않아도 도메인을 이해하고 작업을 설계할 수 있게 두는 누적 자산이다.
작업을 시작할 때 고칠 도메인의 spec 을 먼저 읽고, 작업이 끝나면 바뀐 사실을 spec 과 @MX 주석에 함께 반영한다.

## 도메인 spec

`domains/<도메인>.md` 에 도메인마다 한 장. 모든 spec 은 같은 세 묶음으로 쓴다.

1. **컨텍스트 내부**: 엔티티(타입)의 필드, 비즈니스 규칙(정책 분기·핵심 상수), 핵심 설계 결정(왜 이 구조인가)
2. **외부 노출(Published Language)**: 라우트·컴포넌트 props·export 함수 시그니처, 이벤트·저장소 계약(CustomEvent, localStorage 키, HTTP 요청·응답), 에러 계약(빌드를 멈추는 조건, API 에러 응답)
3. **Context Map**: 다른 도메인에 대한 의존과 그 방식(누가 누구를 import/호출하는가)

| 도메인 | 범위 |
| --- | --- |
| [posts](domains/posts.md) | 글(MDX) 읽기·검증·frontmatter, 글 페이지, 목차·이어서 읽기 |
| [playgrounds](domains/playgrounds.md) | 글 안에서 쓰는 MDX 컴포넌트(그림·코드 블록·Playground) |
| [browse](domains/browse.md) | 첫 화면 목록, 분류 탭·역량 칩, 물방울 인터랙션 |
| [lab](domains/lab.md) | 연구실 실험 목록과 썸네일 카드 |
| [shell](domains/shell.md) | 공통 머리말·테마·모드 메뉴·디자인 토큰(globals.css) |
| [search](domains/search.md) | `/`·⌘K 검색 팔레트와 자연어 질문 API(`/api/ask`) |
| [museum](domains/museum.md) | 박물관 모드(3D 기록관, 두루마리 읽기, 관람 수첩) |
| [stats](domains/stats.md) | 방문자 수·글 조회수(Supabase Postgres)와 BEST·HOT 표식 |

spec 의 사실은 코드에서 확인한 것만 쓴다. 숫자도 코드에 있는 상수만 쓴다. 공개 저장소이므로 회사·고객사 이름이나 내부 주소를 쓰지 않는다.

## @MX 주석

코드 안에서 에이전트와 사람이 먼저 봐야 할 곳을 표시한다. 형식은 `// @MX:<태그>: 내용`(CSS 는 `/* @MX:<태그>: 내용 */`), 한국어로 쓴다.

| 태그 | 언제 | 함께 쓰는 줄 |
| --- | --- | --- |
| `@MX:SPEC` | 모든 코드 파일 머리. 이 파일이 속한 도메인 spec 경로 | — |
| `@MX:NOTE` | 모든 코드 파일 머리에 한 줄(파일의 역할). 그 밖에 코드만 봐서는 모를 의도·맥락 | — |
| `@MX:ANCHOR` | 다른 파일 여러 곳(대략 3곳 이상)이 기대는 계약(export 함수·타입·상수). 바꾸면 호출하는 쪽이 같이 바뀌어야 한다 | `@MX:REASON`: 누가 기대는가 |
| `@MX:WARN` | 건드리면 깨지기 쉬운 곳(프레임워크 제약, 순서 의존, 실제로 겪은 버그 자리) | `@MX:REASON`: 왜 위험한가 |
| `@MX:TODO` | 아직 안 한 일. 발행 전에 지우거나 해결한다 | — |

- `'use client'` 는 파일 첫 줄에 그대로 두고, 머리 주석은 그 아래에 둔다.
- 기존 설명 주석은 지우지 않는다. 같은 말을 태그로 되풀이하지 말고, 태그가 필요한 곳에만 붙인다.
- 태그는 코드가 바뀌면 같이 고친다. 사실과 다른 태그는 없는 것보다 나쁘다.
